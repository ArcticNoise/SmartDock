FitGrid(int, double, double, double, double, double, double, double, double, double, double, int)

Snaps a floating toolbar to a whole-cell grid that shows every button. GridShape(int, int, bool) is the same wrap once a line count is known. count is the number of buttons. Zero is treated as one cell, the minimum. cellWidth and cellHeight are one button; a non-positive value is 1. width and height are the window size being asked for. Horizontal fills each row and wraps. Vertical fills each column and wraps. A result at least as wide as it is tall is horizontal, including a square. Anything taller is vertical. The chrome arguments are the window size outside the button grid for that orientation. horizontalMinWidth and verticalMinWidth keep the caption usable. axis is 0 when the pointer is moving the width, 1 when it is moving the height, and 2 when both sides of a saved size matter. The snapped size is the chrome plus whole cells, so the window has no empty strip beside the grid.

HitSites(ReadOnlySpan<ToolBarSite>, string, ReadOnlySpan<ToolBarBarRect>, ReadOnlySpan<ToolBarBandRect>, ReadOnlySpan<ToolBarTrayRect>, double, double)

Picks the topmost window under the pointer and the pane under it in that window, then a drop in this order: the outer TargetBand of the main window, a band of that window, a band of the pane, an empty edge of the main window when the point is not inside a window tray, a tray of the main window, a tray of the pane, the main window's EdgeSlop, then the pane's edge. An empty edge wins over the slop of a tray on another side, and a point inside that tray still uses the tray. With no pane toolbars this is Hit(DockRect, string, ReadOnlySpan<ToolBarBarRect>, ReadOnlySpan<ToolBarBandRect>, ReadOnlySpan<ToolBarTrayRect>, double, double, string, string) on the main window. A pane edge that lies within EdgeSlop of the window edge catches the next EdgeSlop inward, so it stays reachable. A floating pane window is not a target: its outside edges, bands, and trays are skipped, and a pane inside it still docks. Anything else floats. No allocations.

public static ToolBarDrop HitSites(ReadOnlySpan<ToolBarSite> sites, string dragId, ReadOnlySpan<ToolBarBarRect> bars, ReadOnlySpan<ToolBarBandRect> bands, ReadOnlySpan<ToolBarTrayRect> trays, double x, double y)

Pack(ReadOnlySpan<ToolBarPackItem>, double, Span<double>)

Positions one band along its axis. positions[i] is the start of items[i]. Start-aligned items pack from 0 in index order, index 0 nearest the start, and Offset is the gap before each one. End-aligned items pack from bandLength toward the start, index 0 nearest the far edge, and the offset is the gap after the far edge or the outer neighbour. A non-positive or non-finite length packs the end-aligned items immediately after the start-aligned ones. When the band is too narrow, every end-aligned item shifts so the innermost one starts where the start-aligned items end. End-aligned items may extend past the band. They do not overlap start-aligned items.

public static void Pack(ReadOnlySpan<ToolBarPackItem> items, double bandLength, Span<double> positions)

Place(List<ToolBarEntry>, string, ToolBarDrop, double, double, double, double, double, double, double)

Writes drop onto the toolbar and reindexes that band. A float keeps the docked edge, band, index, offset, and alignment for DockBack(List<ToolBarEntry>, string). When bandLength is positive, PinsToEnd(double, double, double) decides the end: a trailing edge inside EndSnap of the far end packs there with the other end-aligned toolbars, and a drop that misses that zone packs from the start at the drop index and offset. Without a band length, an end-aligned toolbar dropped on the same band after its start-aligned toolbars keeps that alignment and its offset. Index counts the band's toolbars in screen order, start-aligned ones first. End-aligned toolbars keep their indexes when a start-aligned one is placed.
