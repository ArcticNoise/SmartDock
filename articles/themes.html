Themes

DockManager.Theme is a dependency property. Set it to DockThemeKind.Dark (the default), Light, or Blue, or bind it. The palette lives in a dictionary the manager merges. A Dock.* entry in DockManager.Resources is left in place and wins, including after the manager loads and after Theme changes. The same entry is copied onto floating windows, the guide overlay, the auto-hide flyout, toolbar windows, the toolbar name dialog, the Edit Custom Toolbars dialog, and the Delete Toolbar confirmation window. An override added after one of those windows exists is copied the next time Theme is assigned, including to the value it already has, and when that window is created. The pane switcher follows the theme. Open chrome repaints in place. The theme is not saved with the layout.

public static void UseLight(DockManager dock)
{
    dock.Theme = DockThemeKind.Light;
}

To use the dock palette outside the manager, for example in a dictionary merged into Application.Resources, call DockTheme.Apply on any FrameworkElement or ResourceDictionary.

public static void ApplyBlue(FrameworkElement element)
{
    DockTheme.Apply(element, DockThemeKind.Blue);
}

The chrome looks brushes up by resource key, not through the static brush properties. The keys are Dock.Workspace, Dock.Panel, Dock.Chrome, Dock.Header, Dock.Border, Dock.Text, Dock.Muted, Dock.Accent, Dock.AccentSoft, Dock.AccentInactive, Dock.Guide, Dock.GuideButton, Dock.GuideBorder, Dock.Hover, and Dock.Font. DockTheme exposes each name as a *Key constant, for example DockTheme.WorkspaceKey. Dock.AccentInactive is the edge of a selected tab or lone caption whose pane is not active. Dark, light, and blue each define it. A DockCustomTheme dictionary may set Dock.AccentInactive, and a local override wins like the other Dock.* keys.

New Toolbar, Rename, Edit Custom Toolbars, and Delete Toolbar use a separate window, and it reads the same keys. The window background is Dock.Panel and the edge is Dock.Border. The caption is Dock.Chrome with Dock.Text. The text box uses Dock.Chrome, Dock.Text for the text and the caret, and Dock.Border, and that border becomes Dock.Accent while the box has focus. The toolbar list uses Dock.Panel, Dock.Text, and Dock.Border. The selected row uses Dock.AccentSoft. OK, Cancel, Rename, Delete, and Close use Dock.Chrome, Dock.Text, and Dock.Border. Hover uses Dock.Hover, a press uses Dock.AccentSoft, and keyboard focus uses Dock.Accent plus Dock.FocusVisual. A custom theme and a Dock.* entry on the manager reach these dialogs, including while one is open. An empty or duplicate name still leaves the dialog up, with no extra message. Delete asks in the Edit Custom Toolbars dialog. Delete Toolbar on Add or Remove Buttons asks in its own window with the same caption, text, and buttons.

The static brushes on DockTheme always hold the dark palette, and the chrome doesn't use them. Don't reference DockTheme.Border or DockTheme.Panel with x:Static: those names match WPF types, and the markup compiler resolves them as types.

DockTheme.CreateScrollBarResources returns styles for the scroll bar, tool tip, and focus visual. The manager, each floating window, the switcher, the toolbar name dialog, the Edit Custom Toolbars dialog, and the Delete Toolbar confirmation window merge it already. Merge your own copy if you want the same scroll bars elsewhere in the app.

DockTheme.CreateMenuResources returns menu, context menu, menu item, and separator styles in the dock colors. Nothing merges it for you. Merge it into application resources if your menus should match the dock, or leave it out to keep the system look. A copy merged into the host window follows Theme changes.

A shared dictionary

DockManager.CustomTheme points a manager at a resource dictionary you already share across windows. Subclass DockCustomTheme and return that dictionary's Uri. You do not write the Uri on each window.

public sealed class EditorDockTheme : DockCustomTheme
{
    public override Uri GetResourceUri()
        => new("/MyApp;component/Themes/EditorDock.xaml", UriKind.Relative);
}

The dictionary can hold other styles. SmartDock reads Dock.* and DockMenu.* only, including keys that come from a dictionary merged into it. A key it does not define stays on Theme.

<ResourceDictionary xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
                    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml">
    <SolidColorBrush x:Key="Dock.Chrome" Color="#FF2A241C" />
    <SolidColorBrush x:Key="Dock.Panel" Color="#FF3A3228" />
    <SolidColorBrush x:Key="DockMenu.Panel" Color="#FF3A3228" />
</ResourceDictionary>

<sd:DockManager Theme="Dark">
    <sd:DockManager.CustomTheme>
        <local:EditorDockTheme />
    </sd:DockManager.CustomTheme>
</sd:DockManager>

When several brushes define the same key, the winner is:

  1. A Dock.* or DockMenu.* key set on DockManager.Resources itself.
  2. The same key in the custom dictionary.
  3. DockManager.Theme.

Setting, replacing, or clearing CustomTheme repaints chrome that is already open, including the toolbar name dialog, the Edit Custom Toolbars dialog, and the Delete Toolbar confirmation window, and windows opened later pick it up. Changing Theme leaves the custom keys in place. Set CustomTheme to null to go back to the palette. A Uri that cannot be loaded throws when you set the property, and the previous theme stays. The choice is not saved with the layout.
