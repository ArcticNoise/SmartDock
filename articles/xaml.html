Working in XAML

You can declare the layout, toolbars, key bindings, and theme on the window itself. MarkupWindow does all of that, and its code-behind only calls InitializeComponent, which any window with x:Class needs.

<Window x:Class="SmartDock.Docs.Samples.MarkupWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:dock="clr-namespace:SmartDock;assembly=SmartDock"
        xmlns:local="clr-namespace:SmartDock.Docs.Samples"
        xmlns:model="clr-namespace:SmartDock;assembly=SmartDock.Core"
        Title="SmartDock"
        Height="640"
        Width="960">
  <Window.DataContext>
    <local:ThemeChoice />
  </Window.DataContext>
  <Window.InputBindings>
    <KeyBinding Key="F"
                Modifiers="Control"
                Command="{x:Static dock:DockCommands.ToggleFloat}"
                CommandTarget="{Binding ElementName=Dock}" />
    <KeyBinding Key="H"
                Modifiers="Control"
                Command="{x:Static dock:DockCommands.ToggleAutoHide}"
                CommandTarget="{Binding ElementName=Dock}" />
  </Window.InputBindings>
  <dock:DockManager x:Name="Dock" local:SampleContent.Prepare="True" Theme="{Binding Theme}">
    <dock:DockManager.ToolBars>
      <ToolBar dock:DockToolBar.Id="standard"
               dock:DockToolBar.Title="Standard"
               dock:DockToolBar.Edge="Top"
               dock:DockToolBar.Band="0"
               dock:DockToolBar.Alignment="End"
               dock:DockToolBar.PaneId="solution">
        <Button dock:DockToolBar.Key="save" Content="Save" />
        <Button Content="Float"
                Command="{x:Static dock:DockCommands.ToggleFloat}"
                CommandTarget="{Binding ElementName=Dock}" />
        <Button Content="Blue" Command="{Binding UseBlue}" />
      </ToolBar>
    </dock:DockManager.ToolBars>
    <dock:DockManager.Layout>
      <model:DockLayout>
        <model:DockLayout.Root>
          <model:SplitNode Id="root" Orientation="Horizontal">
            <model:SplitNode.Children>
              <model:SplitChild Proportion="0.25">
                <model:SplitChild.Node>
                  <model:TabGroupNode Id="tools" Kind="Tool">
                    <model:TabGroupNode.Panels>
                      <model:DockPane ContentId="solution" Title="Solution Explorer" Kind="Tool" CanClose="False" CanAutoHide="True" />
                      <model:DockPane ContentId="properties" Title="Properties" Kind="Tool" />
                    </model:TabGroupNode.Panels>
                  </model:TabGroupNode>
                </model:SplitChild.Node>
              </model:SplitChild>
              <model:SplitChild Proportion="0.75">
                <model:SplitChild.Node>
                  <model:TabGroupNode Id="docs" Kind="Document">
                    <model:TabGroupNode.Panels>
                      <model:DockPane ContentId="program" Title="Program.cs" />
                      <model:DockPane ContentId="readme" Title="README.md" />
                    </model:TabGroupNode.Panels>
                  </model:TabGroupNode>
                </model:SplitChild.Node>
              </model:SplitChild>
            </model:SplitNode.Children>
          </model:SplitNode>
        </model:DockLayout.Root>
      </model:DockLayout>
    </dock:DockManager.Layout>
  </dock:DockManager>
</Window>

Layout

The tree uses the same node types as Layout. A DockPane in XAML only names a content id. It doesn't create the control, and RegisterContent is a method, so markup can't call it. This sample works around that with local:SampleContent.Prepare, an attached property defined in LayoutWindow.xaml.cs. XAML sets it on the start tag, before the Layout property element, so the content factories are registered before the panes are created.

Theme is bound to ThemeChoice, a small class with a DockThemeKind property. The manager repaints whenever that value changes.

using System.ComponentModel;
using System.Windows.Input;

namespace SmartDock.Docs.Samples;

public sealed class ThemeChoice : INotifyPropertyChanged
{
    private DockThemeKind _theme = DockThemeKind.Light;

    public ThemeChoice() => UseBlue = new RelayCommand(_ => Theme = DockThemeKind.Blue);

    public DockThemeKind Theme
    {
        get => _theme;
        set
        {
            if (_theme == value)
                return;
            _theme = value;
            PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(nameof(Theme)));
        }
    }

    public ICommand UseBlue { get; }

    public event PropertyChangedEventHandler? PropertyChanged;
}

The Blue button runs UseBlue, which sets Theme to Blue. Themes lists the three palettes. To change individual colors, put Dock.* brushes in DockManager.Resources. They win over the theme and reach floating windows, the guide overlay, the auto-hide flyout, and toolbar windows. Styling and templates lists the keys.

Content from a collection

If your items are the content, you don't need factories at all. DocumentsSource and ToolsSource take any IEnumerable. An item that is a UIElement becomes the pane body. Any other item is shown through DocumentTemplateSelector, then DocumentTemplate, then the implicit DataTemplate for its type. Tools use ToolTemplateSelector, ToolTemplate, and the same implicit lookup.

The implicit template is found with TryFindResource on the manager, which checks the manager's own resources, then parents such as the window, then application resources. The lookup runs when the item is added and again when the manager gets a parent and when it loads, so the templates can live in Window.Resources, as they do in MarkupDocumentsWindow. A template you add after the manager has loaded isn't applied to items that are already open. A template that came from DocumentTemplate, ToolTemplate, or a selector is never replaced by this lookup. This window's code-behind also only calls InitializeComponent.

<Window x:Class="SmartDock.Docs.Samples.MarkupDocumentsWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:dock="clr-namespace:SmartDock;assembly=SmartDock"
        xmlns:local="clr-namespace:SmartDock.Docs.Samples"
        Title="SmartDock"
        Height="640"
        Width="960">
  <Window.Resources>
    <DataTemplate DataType="{x:Type local:MarkupDocument}">
      <TextBox Text="{Binding Text, UpdateSourceTrigger=PropertyChanged}"
               AcceptsReturn="True"
               BorderThickness="0" />
    </DataTemplate>
    <DataTemplate DataType="{x:Type local:MarkupTool}">
      <TextBlock Text="{Binding Text}" Margin="12" TextWrapping="Wrap" />
    </DataTemplate>
  </Window.Resources>
  <dock:DockManager>
    <dock:DockManager.Resources>
      <Style x:Key="DocumentItem" TargetType="dock:DockItem">
        <Setter Property="Title" Value="{Binding Title}" />
        <Setter Property="ContentId" Value="{Binding ContentId}" />
        <Setter Property="CanClose" Value="{Binding CanClose}" />
        <Setter Property="CanFloat" Value="{Binding CanFloat}" />
      </Style>
      <Style x:Key="ToolItem" TargetType="dock:DockItem">
        <Setter Property="Title" Value="{Binding Title}" />
        <Setter Property="ContentId" Value="{Binding ContentId}" />
        <Setter Property="CanClose" Value="{Binding CanClose}" />
        <Setter Property="CanFloat" Value="{Binding CanFloat}" />
        <Setter Property="CanAutoHide" Value="{Binding CanAutoHide}" />
        <Setter Property="HideOnClose" Value="{Binding HideOnClose}" />
      </Style>
    </dock:DockManager.Resources>
    <dock:DockManager.DocumentItemStyle>
      <StaticResource ResourceKey="DocumentItem" />
    </dock:DockManager.DocumentItemStyle>
    <dock:DockManager.ToolItemStyle>
      <StaticResource ResourceKey="ToolItem" />
    </dock:DockManager.ToolItemStyle>
    <dock:DockManager.DocumentsSource>
      <x:Array Type="{x:Type local:MarkupDocument}">
        <local:MarkupDocument ContentId="program" Title="Program.cs" Text="class Program" />
        <local:MarkupDocument ContentId="readme" Title="README.md" Text="Notes" CanClose="False" />
      </x:Array>
    </dock:DockManager.DocumentsSource>
    <dock:DockManager.ToolsSource>
      <x:Array Type="{x:Type local:MarkupTool}">
        <local:MarkupTool ContentId="solution" Title="Solution Explorer" Text="Projects" CanClose="False" CanAutoHide="True" />
      </x:Array>
    </dock:DockManager.ToolsSource>
  </dock:DockManager>
</Window>

DocumentItemStyle and ToolItemStyle target DockItem, with the source item as the data context. You can set Title, ContentId, Icon, CanClose, CanFloat, CanAutoHide, and HideOnClose. A pane with an empty title shows its content id instead. An empty ContentId is replaced with item- followed by eight hex digits. A saved layout finds an item again only when its id is the same string, so give items fixed ids if you save layouts. Icon isn't saved in the layout file.

If a tool's style doesn't set CanAutoHide, it defaults to true, the same as DockTree.Tool. This window binds it, so the value comes from MarkupTool. MarkupDocument and MarkupTool are in MarkupDocument.cs.

x:Array doesn't implement INotifyCollectionChanged, so adding to it later has no effect. Use an ObservableCollection when the list changes; MVVM shows how.

The first pane added to an empty manager becomes the root. After that, a new document joins the main-tree document group that last held the active document. If there isn't one, it joins the first document group, and if there are no document groups, it goes to the right of the root at 0.75. A new tool joins the first tool group, or goes to the left of the root at DockEdit.DefaultProportion (0.25). An id that is already docked, floating, auto-hidden, or hidden stays where the layout put it.

Toolbars

The toolbar in MarkupWindow uses the DockToolBar attached properties. Edge, Band, Alignment, and PaneId only set where it starts. Once the toolbar has been shown or dragged, its saved position wins, and changing these properties doesn't move it. PaneId="solution" starts the toolbar on that pane, and an unknown pane id falls back to the main window's top tray. Toolbars lists the other attached properties.

DockToolBar.Key on the Save button is the key that customization is saved under. A button with no key, Name, content id, or string tooltip gets a key that lasts only for the session. That key isn't saved, and the button doesn't appear in the customize menu.

Commands

DockCommands holds routed commands that the manager already handles: ClosePane, NextDocument, PreviousDocument, ToggleFloat, ToggleAutoHide, SaveLayout, and LoadLayout. The manager and each floating window have handlers for them. A button outside the manager needs CommandTarget set to the manager, because otherwise the command routes from wherever focus is and may never reach it. A button or menu item inside the manager can leave CommandTarget unset.

ToggleFloat, ToggleAutoHide, SaveLayout, and LoadLayout have no default key, so the window adds Ctrl+F and Ctrl+H with key bindings. A KeyBinding adds a gesture without removing the defaults: ClosePane is still Ctrl+F4, NextDocument Ctrl+PageDown, and PreviousDocument Ctrl+PageUp. To change a default, replace the command's InputGestures. DockCommands is static, so the change applies to every manager in the process. See Keyboard.

ToggleFloat floats the active pane at (80, 80), 480 by 360, if it's allowed to float, and docks a floating pane back. ToggleAutoHide does nothing when the active pane can't auto-hide, as with the Properties pane here, which leaves CanAutoHide false. SaveLayout writes the current layout to SavedLayout, which MVVM binds. LoadLayout reads that string and applies it again, which is how you restore a save after the user has moved panes. It does nothing when SavedLayout is null or empty.

What still needs code

RegisterContent can't be called from markup, and a DockPane in XAML doesn't create its control. Either call RegisterContent before Layout is assigned, or wrap it in an attached property the way SampleContent.Prepare does. If you'd rather avoid both, use DocumentsSource and ToolsSource, which don't need it.
