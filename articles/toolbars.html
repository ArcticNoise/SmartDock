Toolbars

Put ordinary WPF ToolBar controls in DockManager.ToolBars and the dock lays them out in trays on the main window or on a pane, including a pane inside a floating window. A floating pane window has no trays of its own: the caption and the outside edges are not drop targets. An open auto-hide flyout is a pane, so a toolbar can dock to it. If you never touch ToolBars or ToolBarsSource, no tray is built.

Set DockToolBar attached properties on each toolbar to say where it goes:

Property Meaning
Id Stable id. A saved entry is matched to the toolbar by this string. The toolbar's Name is used when Id is empty.
Title Caption of a floating toolbar, and the label in the tray menu.
Edge Top, Bottom, Left, or Right. The default is Top.
Band Row or column on that edge. Band 0 is the outer side: the top of a top tray, the bottom of a bottom tray, the left of a left tray, and the right of a right tray.
BandIndex Position within the band.
Offset Gap before the toolbar, in device-independent pixels.
Alignment Start packs from the left of a horizontal band or the top of a vertical one. End packs from the right or the bottom. Start is the default. Dragging a toolbar so its trailing edge reaches the far end, or comes within 16 device-independent pixels of it, pins it to End. Dragging it back off that zone packs it from the start.
PaneId Content id of the pane that hosts the toolbar. Empty means a window tray. A pane that is not in the layout uses the main window's top tray.
IsVisible False hides the toolbar and keeps a floating window's bounds. True shows it again.
ShowOverflow When true, the toolbar uses the leftover space in the band and shows an overflow chevron. The default is false.
IsCustomizable When false, that toolbar has no customize menu and ignores Alt+drag. The default is true.

Edge, Band, BandIndex, Offset, Alignment, and PaneId only set the starting place. Once the toolbar has been shown or dragged, its layout entry decides where it is, and changing these properties no longer moves it. Reset on the customize menu is what puts the toolbar back on this place.

<Window x:Class="SmartDock.Docs.Samples.ToolbarWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:dock="clr-namespace:SmartDock;assembly=SmartDock"
        Title="SmartDock"
        Height="640"
        Width="960">
  <dock:DockManager x:Name="Dock">
    <dock:DockManager.ToolBars>
      <ToolBar dock:DockToolBar.Id="standard"
               dock:DockToolBar.Title="Standard"
               dock:DockToolBar.Edge="Top"
               dock:DockToolBar.Band="0"
               dock:DockToolBar.Alignment="Start">
        <Button Content="Save" />
      </ToolBar>
    </dock:DockManager.ToolBars>
  </dock:DockManager>
</Window>

The same thing in code:

public static void AddAligned(DockManager dock)
{
    var bar = new ToolBar();
    DockToolBar.SetId(bar, "standard");
    DockToolBar.SetTitle(bar, "Standard");
    DockToolBar.SetEdge(bar, ToolBarEdge.Top);
    DockToolBar.SetBand(bar, 0);
    DockToolBar.SetBandIndex(bar, 0);
    DockToolBar.SetOffset(bar, 0);
    DockToolBar.SetAlignment(bar, ToolBarAlignment.End);
    bar.Items.Add(new Button { Name = "save", Content = "Save" });
    dock.ToolBars.Add(bar);
}

To bind toolbars from view models, use ToolBarsSource. Each item becomes a ToolBar built from ToolBarTemplateSelector if set, else ToolBarTemplate, else the implicit data template. Placement comes from DockToolBarItem instead of the attached properties: bind its properties in a style assigned to ToolBarItemStyle. The buttons themselves stay in each toolbar's own Items or ItemsSource.

Floating toolbars

Drag the grip along the band to slide the toolbar. Drag it out of the tray and it turns into a floating window that follows the pointer; the window is shown on that move, under the pointer, while the button is still down, and release leaves it there. Dragging the caption moves the window with the pointer on each move, the same way a pane float moves. An edge that does not have a band yet shows the drop line in the guide overlay, so a floating toolbar and native pane content do not cover it, and it does not open a tray while the button is down. The pointer over a pane draws the edge guides. The caption and the outside edges of a floating pane window draw no band, and releasing there leaves the toolbar floating. A pane inside that window still takes the drop. The main window's trays are unchanged. Right and bottom lines sit inside the window. A point in an empty edge's zone docks on that edge even when it is also in the slop of a tray on another side. A point inside that tray still uses the tray. The band is created when the toolbar is dropped there. Dropping somewhere else, or pressing Escape, leaves that edge empty. A band that is already there still takes the toolbar while the pointer is down. A new row in a tray that already has bands waits for the drop too, because that row would make the tray taller. The window starts horizontal, including a single line torn off the left or right edge. Moving back over a tray in the same drag docks it again. Double-click the grip of a floating toolbar to send that toolbar back to the band it came from. The close button on the caption hides it, and showing it again reopens the window at the same bounds. A window that holds several toolbars is described below.

A floating toolbar can stack its buttons. Right-click the caption and check Vertical. The same item is on Add or Remove Buttons while the toolbar is floating. The grip moves to the top and the Add or Remove Buttons chevron to the bottom. The caption stays on top and does not draw the title; the tooltip is the full text. A horizontal title that does not fit is trimmed, and the tooltip shows the full text. The close button stays usable. The window measures again after the orientation change, including a toolbar the host restyles, so every button stays inside it at any display scale, and the toolbar's overflow chevron appears only when a button does not fit. A vertical float hides the caption grip and makes the caption outside the close button the drag handle, so it is as wide as its button column or the close button (32/3 DIP, about 10.7, with its glyph at two thirds of the template size) when the column is narrower. A column wider than that close button keeps a drag area beside it. Unchecking Vertical measures the window back to the horizontal size. A horizontal float is as wide as its buttons, grip, and chevron, and an empty one is at least as wide as its caption. The button band is the same height as the grip and the chevron, docked or floating: the grip and the chevron start and end where the band does across the row, so a band inset by a template margin, a toolbar margin or height limit, or tray padding still lines up with them. On a vertical row the chevron's width from its style runs down the row and the chevron is as wide as the band. Switching that empty bar to vertical and back measures it again. Combined toolbars in one vertical float share one width, with a separator between them. Drag the right or bottom edge to resize the window. The buttons wrap to fill it: a horizontal window fills each row and then the next, and a vertical window fills each column and then the next. The window snaps to whole cells, so a row of buttons stays one height and there is no empty strip. Each button stays the size the toolbar's own template gave it in one line, including an image with no width or height. The grid keeps the fill, line, corner, padding, and margin of the outermost border the toolbar's template draws around its PART_ToolBarPanel, so a host-styled float looks the same as a grid as it does as one row. A DynamicResource or binding on that border stays live on the grid, so a theme or resource change while the window is a grid updates the fill and the line, and they stay when the float is a single row again. A style that limits the toolbar's height or width is lifted while the grid is shown, so the extra rows and columns stay whole, and those limits come back when the float is a single row or column again. The smallest size is one button plus the caption and the frame. A window at least as wide as it is tall is horizontal, and that includes a square. A taller window is vertical. The Vertical check matches that shape as the edge moves. Press Escape, or lose the mouse capture, and the size and orientation stay as they were when the drag started. SaveLayout writes that width and height with the other float bounds, and loading the layout opens the window at that size.

DockManager.SetToolBarFloatVertical and IsToolBarFloatVertical set and read that flag. The setter does nothing while the toolbar is docked. Docking onto a tray, docking back, and Reset clear it. A docked toolbar takes its orientation from the edge: left and right are vertical, top and bottom are horizontal. SaveLayout writes floatVertical only when it is true, so an older file stays the same bytes and loads as horizontal. A file that sets the flag on a toolbar that is not floating loads with it clear.

A float of more than one line keeps that count when it docks onto an edge of the same orientation. Horizontal rows stay rows on a top or bottom tray, including a pane tray. Vertical columns stay columns on a left or right edge. Docking onto the other orientation gives one line. ToolBarEntry.Lines is that count. Zero means one line and is left out of the file, so a layout saved before line counts existed loads as one line and saves back unchanged. A count of one is also stored as zero. ToolBarBands.SetLines writes it. Every toolbar in one floating window has the same value. ToolBarBands.GridShape is the wrap the float grid uses, and the docked toolbar uses that same grid. The band grows to the grid. The grip and the chevron still start and end where that frame does. A toolbar with ShowOverflow still puts the buttons that do not fit behind the chevron, and the line count stays. Undocking a count above one opens the same grid, so a multi-line toolbar torn off the left or right edge comes back vertical. A single line torn off a side stays horizontal. Reset sets the count back to one line. The count is the number of lines the float shows, so a float with enough buttons hidden to fit one line docks as one line. Merging two floats into one window, or splitting a shared float, resets that window to one line. On a tray too short for the grid, the buttons that do not fit go to the chevron's overflow list, as on a single line, and come back when the tray is long enough. Checking or unchecking Vertical does too, because that sizes the window to one column or one row.

Several toolbars can share one floating window. Drag any grip over that window and a 2 device-independent-pixel line shows where it will land. The line is drawn in the guide overlay, so it sits above the float. Drop to insert the toolbar, and the window grows to fit. Drag a grip inside the window to change the order. Drag it out, past the same slop the trays use, and that toolbar becomes its own float under the pointer. The others stay. When one is left, it is an ordinary float again. Dragging the caption moves the whole window. Dropping the caption on a tray or a dock edge docks every visible toolbar in the window, in order. Double-click the caption to send them all back to the bands they left. Double-click one grip to send only that toolbar back. The caption title is the non-custom titles joined with a comma. It trims when it does not fit, and the tooltip is the full list, including a custom toolbar's name. That name is not drawn in the caption.

The caption close button and Alt+F4 hide every visible toolbar in the window. They stay floating, in the same group, at the same bounds. Showing one from the tray menu opens the window again at that place. Showing another puts it back in its order. Unchecking one in the tray menu hides only that toolbar. The window shrinks, or hides when nothing in it is visible. Reset on one toolbar docks only that one at its declared place.

The orientation belongs to the window. Flipping it flips every toolbar in it. A toolbar dropped into a vertical float becomes vertical. A toolbar torn out of one stays vertical.

DockManager.MergeFloatingToolBars(id, targetId, index) puts a toolbar into the window that holds targetId. index is the gap, and a negative index means the end. SplitFloatingToolBar(id) takes one toolbar out at the same place. SaveLayout writes floatId and floatIndex only when they are set, so an older file stays the same bytes. A floatId on a toolbar that is not floating is rejected. A group of one drops floatId when the file is loaded. windowId is not this group. An older file may still have windowId from a toolbar that was docked on a floating pane window's edge. Loading that layout into the dock moves the toolbar to the main window's top tray. A toolbar that was already floating stays floating, and docking it back uses that tray. The next save leaves windowId out.

A toolbar with PaneId set travels with its pane when the pane floats, docks somewhere else, changes tabs, or auto-hides. When the pane closes, the toolbar goes back to its declared place.

Customize menu and hide or show

Users can customize toolbars unless you turn it off. ToolBarCustomizationEnabled is true by default.

  • Right-click an empty part of a tray, the grip, or the chevron to get a menu of all toolbars, listed by title (or id when the title is empty). A floating toolbar opens the same menu from its empty band, its grip, or its chevron. The caption keeps its own menu. A button opens this list only when it has no menu of its own: if the button, or anything between the click and the toolbar, has a context menu, that menu opens and the list does not. If the button opens its own popup from the right-click, the list stays closed, even when that handler does not set Handled. A button with no menu of its own still opens the list. A right-click on an item in the toolbar's overflow keeps the overflow open and follows the same rule. The same applies to a toolbar on a pane in an auto-hide flyout. Visible ones are checked; uncheck one to hide it. Checking or unchecking a toolbar leaves the menu open. New Toolbar and Edit Custom Toolbars close it. Edit Custom Toolbars is disabled when there are no custom toolbars. An item does not repeat its label as a tooltip. A tooltip that adds something else is placed on that item and uses the dock colors.
  • The customize button on a toolbar opens "Add or Remove Buttons". Every button with a stable key has a check item there; uncheck it to hide the button. While the toolbar is floating, the menu also has a checkable Vertical item. Reset undoes the button changes and puts that toolbar back on the edge, band, index, offset, and alignment declared on it. A floating toolbar docks there. Other toolbars in a shared window stay floating. Reset also clears a vertical float and restores one line. A hidden toolbar is shown. A custom toolbar also has Delete Toolbar next to Reset. A built-in toolbar does not. Delete asks first in a dialog styled like New Toolbar, then removes the toolbar. It works on a window tray, a pane tray, and a float. Deleting a floating toolbar closes its window.
  • Alt+drag a button to reorder it, move it to another toolbar, or drop it outside the toolbars to hide it.

Customization is saved per button key. The key is DockToolBar.Key if set. Otherwise it comes from ToolBarItemKeyPath, then the element's Name, ContentId, Id, or a string ToolTip or ToolTipText. A button with none of these gets a key for the current session only: its changes are not saved, and it doesn't appear in the customize menu. Give your buttons names or keys.

Set ToolBarCustomizationEnabled to false to turn off Alt+drag, the customize menu, and the tray menu everywhere. Set IsCustomizable to false to do the same for one toolbar.

By default the dock keeps the user's button order as an overlay and leaves your item collections alone. Set ToolBarMoveItemsInSource to true if a reorder or a move between toolbars should edit the source lists too. Only do that when those lists are writable.

ToolBarCustomizationChanged fires after a button is reordered, moved, copied, removed, hidden, shown, or reset, and when a toolbar is created, renamed, deleted, shown, or hidden. ToolBarId names the toolbar. ItemKey is the button's key, or null when the change is about the toolbar itself. FromToolBarId is set when a button came from another toolbar.

Custom toolbars

The tray menu has New Toolbar. It asks for a name and floats an empty toolbar near the pointer. DockManager.CreateCustomToolBar does the same and floats it at (48, 48). The name is trimmed. An empty name, or a name another toolbar already uses, is rejected. Enter accepts the dialog and Escape cancels it. The dialog follows the dock theme, including a custom theme. Themes lists the brushes.

Edit Custom Toolbars is the next item. It is disabled when there are no custom toolbars. The dialog lists every custom toolbar by name. Pick one and rename it, or delete it. Rename uses the same rule as New Toolbar: the name is trimmed, and an empty name or a name another toolbar already uses leaves the dialog open. Delete asks in the dialog before the toolbar is removed. Deleting a floating toolbar closes its window. The list, the text box, and the buttons use the same brushes as New Toolbar. When the last custom toolbar is deleted, the dialog says there are none.

A custom toolbar is a ToolBarEntry with Custom, Title, and the copied button keys in Items. It has no host collection. The tray menu shows the name. A float shows it as the caption tooltip and the grip tooltip, not as caption text, including when the float is vertical. Right-click its caption or its grip to rename it or delete it. Delete removes that toolbar only. The buttons it copied stay on the toolbars they came from.

Alt+drag onto a custom toolbar copies. The original stays where it is, still visible and enabled. The copy is a stand-in: clicking it clicks the original, and IsEnabled and Visibility follow the original. The stand-in keeps the original button's width and height. It uses the original style when that style's target type fits, and the toolbar's button style otherwise, so a float of copied icon buttons is the same size as the toolbar they came from. An Image or a Path is cloned, so the icon shows in both places. Any other visual is shown as text. Alt+drag inside the custom toolbar reorders the copies. Alt+drag a copy off it, or onto a normal toolbar, removes the copy and does not move the original. Alt+drag onto a normal toolbar still moves the button, and the original collapses there until that toolbar is reset. A plain drag does not move or copy a button.

A separator can be copied the same way. The copy is a real separator. Dropping a separator onto a normal toolbar does not move it.

The custom toolbar is in the tray menu with its own check mark. Add or Remove Buttons lists its copies, and unchecking one hides that copy, not the original. Reset clears the copies and leaves the toolbar where it is, including a float. Reset on a normal toolbar is unchanged. Delete Toolbar is the next item, and only on a custom toolbar. It asks before it removes the toolbar, whether that toolbar is docked, on a pane, or floating. Cancel leaves it. Deleting a float closes the window.

RenameCustomToolBar and DeleteCustomToolBar are the same operations. SaveLayout writes custom, title, and items only when they are set, so an older file stays the same bytes. A custom toolbar with no title, or item ids that are empty or repeated, is rejected. A key whose button is missing at load stays in items and is shown again when that button exists.

Layout persistence

DockManager.SaveLayout writes bands, alignment, floating bounds, a vertical float, a shared float's floatId and floatIndex, visibility, button order, and custom toolbars to DockLayout.ToolBars, and LoadLayout restores them. custom, title, and items are left out when they are the default. floatVertical is left out when it is false. lines is left out when the toolbar is one line. floatId and floatIndex are left out when they are null and zero. A file without a toolBars object loads fine. See Saving and loading layouts.
