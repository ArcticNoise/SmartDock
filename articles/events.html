Events and callbacks

All events are on DockManager. This handler set cancels closing the "readme" pane and records the rest:

public static string? Last { get; private set; }

public static void Watch(DockManager dock)
{
    dock.PaneClosing += (_, e) =>
    {
        if (e.ContentId == "readme")
            e.Cancel = true;
    };
    dock.PaneClosed += (_, e) => Last = e.ContentId;
    dock.PaneStateChanged += (_, e) => Last = e.NewState.ToString();
    dock.ActivePaneChanged += (_, e) => Last = e.NewContentId;
    dock.PaneMounted += (_, e) => Last = e.ContentId;
    dock.PaneUnmounted += (_, e) => Last = e.ContentId;
    dock.LayoutChanged += (_, _) => Last = "layout";
    dock.ToolBarCustomizationChanged += (_, e) => Last = e.ToolBarId;
}

LayoutChanged

Fires after a structural edit, a tab selection change, or a splitter move. Use it to know when to save. Reordering a tab by dragging fires it once, on release. Tearing a pane off into a float fires it as soon as the pane leaves its group. Moving a floating window does not fire it, and neither does a close that a PaneClosing handler cancelled.

PaneClosing and PaneClosed

PaneClosing fires before a pane is removed, with ContentId and Cancel. Set Cancel to keep the pane; the layout stays as it was and LayoutChanged does not fire. This is where you ask about unsaved changes.

It fires for the tab close button, the flyout close button, ClosePane (and so Ctrl+F4), and for a floating window's close button, Alt+F4, or Window.Close. Closing a floating window fires it once for each pane that can close; if any handler cancels, the window stays open and nothing closes. Panes in that window that can't close are docked back without the event, unless they have HideOnClose.

A pane with HideOnClose still gets PaneClosing from the same buttons and from ClosePane, but is then hidden rather than removed, so PaneClosed does not fire.

PaneClosed fires after a user close has removed the pane. It does not fire when Layout is replaced (including LoadLayout and a SavedLayout change that loads), or for RemovePane, HidePane, ShowPane, or EditLayout; those report PaneStateChanged instead. Closing the host window doesn't fire PaneClosing; it only dismisses the floating windows.

PaneStateChanged

Fires when a pane moves between Docked, Floating, AutoHidden, and Hidden, with ContentId, OldState, and NewState. Replacing Layout fires it for every pane whose state changed.

The state says where the pane is in the layout, not whether its content is on screen. A docked pane in an unselected tab, an auto-hidden pane with its flyout closed, or a float that hasn't placed its content yet has no content in a host. Use PaneMounted and PaneUnmounted for that.

ActivePaneChanged

Fires when ActiveContentId changes. OldContentId or NewContentId is null when there was, or is, no active pane. The active pane is the one whose tab was selected last or whose content last got keyboard focus.

To activate a pane from code, call ActivatePane. It selects the tab of a docked or floating pane, opens an auto-hidden pane's flyout, and shows a hidden pane first. An unknown id does nothing.

PaneMounted and PaneUnmounted

PaneMounted fires after a pane's content element has been put in a host: the selected tab of a docked group, a floating window, or an open flyout. PaneUnmounted fires after it has been taken out again. The two always alternate for a given content id.

Moving content to a different host fires PaneUnmounted, then PaneMounted. If the element stays in the same parent, neither fires, so changing a title or icon doesn't. A selected pane stays mounted as long as its group's view is kept.

ToolBarCustomizationChanged

Fires after a toolbar button is reordered, moved, hidden, shown, or reset, and when a toolbar is shown or hidden. See Toolbars.
