Layout

A DockLayout holds the main tree, the floating windows, four auto-hide strips, and any hidden panes. You change it with DockEdit. Each call returns a DockEditResult instead of throwing: a refused edit leaves the tree as it was, and a tree produced by a successful structural edit is valid to save.

Splits and tabs

You can build the tree in code or declare it in XAML. In XAML you need two prefixes: the controls live in the SmartDock assembly and the model types in SmartDock.Core, both under the SmartDock namespace.

Factories still have to be registered before Layout is set. DockManager is sealed, so you can't do that in a subclass constructor. This sample uses an attached property instead: XAML applies attributes on the start tag before property elements, so Prepare runs before the Layout element is assigned.

using System.Windows;
using System.Windows.Controls;

namespace SmartDock.Docs.Samples;

public static class SampleContent
{
    public static readonly DependencyProperty PrepareProperty = DependencyProperty.RegisterAttached(
        "Prepare",
        typeof(bool),
        typeof(SampleContent),
        new PropertyMetadata(false, OnPrepare));

    public static void SetPrepare(DependencyObject element, bool value) => element.SetValue(PrepareProperty, value);

    public static bool GetPrepare(DependencyObject element) => (bool)element.GetValue(PrepareProperty);

    private static void OnPrepare(DependencyObject element, DependencyPropertyChangedEventArgs args)
    {
        if (element is not DockManager dock || args.NewValue is not true)
            return;

        dock.RegisterContent("solution", () => new TreeView());
        dock.RegisterContent("properties", () => new TextBox());
        dock.RegisterContent("program", () => new TextBox());
        dock.RegisterContent("readme", () => new TextBox());
    }
}

<Window x:Class="SmartDock.Docs.Samples.LayoutWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:dock="clr-namespace:SmartDock;assembly=SmartDock"
        xmlns:local="clr-namespace:SmartDock.Docs.Samples"
        xmlns:model="clr-namespace:SmartDock;assembly=SmartDock.Core"
        Title="SmartDock"
        Height="640"
        Width="960">
  <dock:DockManager local:SampleContent.Prepare="True">
    <dock:DockManager.Layout>
      <model:DockLayout>
        <model:DockLayout.Root>
          <model:SplitNode Id="root" Orientation="Horizontal">
            <model:SplitNode.Children>
              <model:SplitChild Proportion="0.25">
                <model:SplitChild.Node>
                  <model:TabGroupNode Id="tools" Kind="Tool">
                    <model:TabGroupNode.Panels>
                      <model:DockPane ContentId="solution" Title="Solution Explorer" Kind="Tool" CanClose="False" CanAutoHide="True" />
                      <model:DockPane ContentId="properties" Title="Properties" Kind="Tool" />
                    </model:TabGroupNode.Panels>
                  </model:TabGroupNode>
                </model:SplitChild.Node>
              </model:SplitChild>
              <model:SplitChild Proportion="0.75">
                <model:SplitChild.Node>
                  <model:TabGroupNode Id="docs" Kind="Document">
                    <model:TabGroupNode.Panels>
                      <model:DockPane ContentId="program" Title="Program.cs" />
                      <model:DockPane ContentId="readme" Title="README.md" />
                    </model:TabGroupNode.Panels>
                  </model:TabGroupNode>
                </model:SplitChild.Node>
              </model:SplitChild>
            </model:SplitNode.Children>
          </model:SplitNode>
        </model:DockLayout.Root>
      </model:DockLayout>
    </dock:DockManager.Layout>
  </dock:DockManager>
</Window>

Proportion is a positive weight. The weights don't need to add up to 1. A tool pane can auto-hide only when CanAutoHide is true. DockTree.Tool sets it for you, but a DockPane declared in XAML leaves it false unless you set it.

TabGroupNode.SelectedIndex is the selected tab, and it is saved with the layout. DockManager.TabPlacement (tool groups) and DocumentTabPlacement (document groups) put the tab strip above or below the content. Both default to Top.

The same tree in code:

public static DockLayout Build()
{
    return DockTree.Create(DockTree.Split("root", SplitOrientation.Horizontal,
        DockTree.Weighted(0.25, DockTree.Tabs("tools", DockKind.Tool,
            DockTree.Tool("solution", "Solution Explorer", canClose: false),
            DockTree.Tool("properties", "Properties"))),
        DockTree.Weighted(0.75, DockTree.Tabs("docs", DockKind.Document,
            DockTree.Document("program", "Program.cs"),
            DockTree.Document("readme", "README.md")))));
}

Docking

DockEdit.Dock moves a pane that is already in the layout. DockSide.Left, Right, Top, and Bottom split the anchor and give the pane DockEdit.DefaultProportion (0.25) unless you pass another weight. DockSide.Center adds the pane as a tab, so the anchor has to be a tab group.

On a live manager, call DockManager.DockPaneTo. It runs the same edit and raises LayoutChanged if the tree changed.

Floating windows

DockEdit.Float takes a pane out of the tree and puts it in a new floating window at the bounds you pass, in device-independent pixels. DockEdit.DockBack puts it back: into the tab group it came from if that group still exists, otherwise into the first main-tree group of the same kind, otherwise into a new group on the right.

A floating window can be saved maximized. Its x, y, width, and height are then the restored bounds, not the maximized ones.

DockManager.FloatPane and DockManager.DockBackPane do the same on a live manager.

A floating window draws its own caption. Drag the caption to move the window, or drop it on a guide to dock the whole window. Double-clicking the caption docks the selected pane back if its previous group is still in the main tree, and maximizes the window otherwise.

On a maximized float, a click or a press without movement leaves it maximized. A double-click restores its earlier place and size. Dragging the caption restores that size under the pointer, and the drag continues with the guides.

Auto-hide

DockEdit.AutoHide moves a tool onto an auto-hide strip on one edge of the dock root. The pane must have CanAutoHide set. DockEdit.Pin docks it back. A new auto-hide entry gets a flyout size of 240 device-independent pixels.

public static void Move(DockLayout layout)
{
    DockEdit.Dock(layout, "readme", "docs", DockSide.Right);
    DockEdit.Float(layout, "readme", 80, 60, 480, 320);
    DockEdit.DockBack(layout, "readme");
    DockEdit.AutoHide(layout, "solution", AutoHideEdge.Left);
    DockEdit.Pin(layout, "solution");
    DockEdit.Select(layout, "program");
}

DockManager.AutoHidePane and DockManager.PinPane do the same on a live manager. The flyout is a native child window of the dock, so it paints above HwndHost content in other panes. Because it is a separate window, it opens at full size instead of sliding in.

Drag and drop guides

Drag a tab along its strip to reorder it. Drag it off the strip to float the pane, then release over a guide to dock it.

While you drag, the dock shows a compass over the tab group under the pointer and one button at the middle of each edge of the host.

  • A compass side button splits that leaf in half. The preview shows the same slice the drop inserts.
  • The compass center button adds the pane as a tab of that group.
  • An edge button docks against the root and takes one quarter of the host.
  • A root-edge button wins when it overlaps the compass.
  • A tool, or a float made of tools, can also drop on an auto-hide strip. A document has no auto-hide target.
  • When the pointer is over another floating window, that window's compass and edge buttons are shown. The topmost window wins, and the window being dragged is skipped.

Guides and the drop preview are drawn in a topmost overlay, so the window you drag never covers them.

Dropping a single torn-off pane calls DockEdit.Dock. Dropping a whole window calls DockEdit.DockWindow: a side button keeps the window's tree as it is, and the center button appends its panes to the target group.

Hide and show

DockEdit.Hide takes a pane out of the tree and stores it on DockLayout.Hidden, along with the place DockEdit.Show puts it back. Hiding works even when CanClose is false. A hidden pane isn't drawn and doesn't appear in the Ctrl+Tab switcher. On a live manager, use DockManager.HidePane and DockManager.ShowPane. Events and callbacks lists the events a hide raises.
