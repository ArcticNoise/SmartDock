Styling and templates

To restyle the chrome, put an implicit style in DockManager.Resources. Floating windows, the guide overlay, the auto-hide flyout, and toolbar windows are separate visual trees and can't see the manager's resources, so the manager copies styles for these types onto each of them: DockTabHeader, DockCaption, DockDropPreview, DockGuideButton, DockToolBarGrip, DockToolBarTray, DockToolBarCaption, DockToolBarDrop, and DockToolBarCustomize. A style in Application.Resources doesn't need copying, because every window already sees it.

Each of those controls picks up the implicit style from its manager when it loads, and assigning Theme makes chrome that is already open pick it up again. If you remove a style from the manager, the control drops it and goes back to the template in Themes/Generic.xaml.

Theme brushes

The chrome reads these keys: Dock.Workspace, Dock.Panel, Dock.Chrome, Dock.Header, Dock.Border, Dock.Text, Dock.Muted, Dock.Accent, Dock.AccentSoft, Dock.AccentInactive, Dock.Guide, Dock.GuideButton, Dock.GuideBorder, Dock.Hover, and Dock.Font. DockTheme has a *Key constant for each one, such as DockTheme.AccentKey. Dock.FocusVisual is the focus rectangle, drawn with Dock.Accent. Dock.GuideBorder is transparent in every built-in theme. Dock.Accent is the bright edge of the active pane. Dock.AccentInactive is the same edge when that tab is selected, or that lone caption is showing, but the pane is not the active one. A Dock.AccentInactive brush in DockManager.Resources wins the same way the other Dock.* keys do.

The theme palette lives in a dictionary that the manager merges into its resources. A Dock.* key you add to DockManager.Resources sits above that dictionary, so it wins over the theme and keeps winning after the manager loads and after Theme changes. Your overrides are also copied onto floating windows, the guide overlay, the auto-hide flyout, toolbar windows, and the toolbar name dialog. If you add an override after one of those windows is open, it reaches that window the next time Theme is assigned (assigning the current value is enough) and every new window gets it when it is created. DockManager.CustomTheme is a shared dictionary of the same keys. It sits under those local keys and over the palette. The New Toolbar and Rename dialog uses these brushes for its window, caption, text box, and buttons. Themes has the class, the order, and which key paints which part.

StylingWindow binds Theme and replaces the accent brushes, including the dim edge:

<Window.DataContext>
  <local:ThemeChoice />
</Window.DataContext>
<dock:DockManager x:Name="Dock" local:SampleContent.Prepare="True" Theme="{Binding Theme}">
  <dock:DockManager.Resources>
    <SolidColorBrush x:Key="{x:Static dock:DockTheme.AccentKey}" Color="#FFC45C26" />
    <SolidColorBrush x:Key="{x:Static dock:DockTheme.AccentSoftKey}" Color="#FFF0D3C2" />
    <SolidColorBrush x:Key="{x:Static dock:DockTheme.AccentInactiveKey}" Color="#FF8C5A3C" />

The Blue button switches the bound property to DockThemeKind.Blue, and the copper accent stays. Don't point x:Static at DockTheme.Border or DockTheme.Panel, because those names clash with WPF types; use the *Key constants. Themes covers DockTheme.Apply, the menu dictionary, and the scroll bar dictionary.

The panes in this sample get their controls from SampleContent.Prepare, because RegisterContent can't be called from markup. Working in XAML explains why.

Tab headers

<Style TargetType="dock:DockTabHeader">
  <Setter Property="Focusable" Value="False" />
  <Setter Property="Margin" Value="2,4,2,0" />
  <Setter Property="Padding" Value="8,4" />
  <Setter Property="Background" Value="{DynamicResource Dock.Header}" />
  <Setter Property="BorderBrush" Value="{DynamicResource Dock.Border}" />
  <Setter Property="BorderThickness" Value="0,0,0,2" />
  <Setter Property="Template">
    <Setter.Value>
      <ControlTemplate TargetType="dock:DockTabHeader">
        <Border x:Name="PART_Chrome"
                Background="{TemplateBinding Background}"
                BorderBrush="{TemplateBinding BorderBrush}"
                BorderThickness="{TemplateBinding BorderThickness}"
                Padding="{TemplateBinding Padding}">
          <StackPanel x:Name="PART_ButtonHost" Orientation="Horizontal">
            <TextBlock Text="{TemplateBinding Title}"
                       VerticalAlignment="Center"
                       Margin="4,0"
                       Foreground="{DynamicResource Dock.Text}"
                       FontFamily="{DynamicResource Dock.Font}" />
          </StackPanel>
        </Border>
        <ControlTemplate.Triggers>
          <Trigger Property="IsSelected" Value="True">
            <Setter Property="Background" Value="{DynamicResource Dock.Panel}" />
            <Setter Property="BorderBrush" Value="{DynamicResource Dock.AccentInactive}" />
          </Trigger>
          <MultiTrigger>
            <MultiTrigger.Conditions>
              <Condition Property="IsSelected" Value="True" />
              <Condition Property="IsActive" Value="True" />
            </MultiTrigger.Conditions>
            <Setter Property="BorderBrush" Value="{DynamicResource Dock.Accent}" />
          </MultiTrigger>
          <Trigger Property="Placement" Value="Bottom">
            <Setter Property="Margin" Value="2,0,2,4" />
          </Trigger>
        </ControlTemplate.Triggers>
      </ControlTemplate>
    </Setter.Value>
  </Setter>
</Style>

PART_ButtonHost is where the header puts its buttons when the template doesn't provide its own. It gets a close button if the pane can close or has HideOnClose, and a pin if the pane can auto-hide. They're added after the template's own children, in the order pin, close, menu. To supply your own button, name a Button PART_Close, PART_Pin, or PART_Menu; the header collapses it whenever that action isn't available. ShowMenu stays false, so a PART_Menu button stays collapsed.

PART_Face is optional. If the template names both PART_Face and PART_ButtonHost, the header lays the face over the accent stroke and the padding; otherwise the template keeps its own layout. PART_Chrome is the outer border. The default style fills it with theme brushes, and a replaced style is left to paint itself.

The header exposes Title, Icon, IsSelected, IsActive, Kind, Placement, IsHovered, ShowClose, ShowPin, and ShowMenu for your template to bind. Dragging, selecting, and closing are handled by the control, so they keep working with any template.

IsActive is true when this header's group holds the active pane. The default selected tab keeps the panel fill and draws a 2px Dock.Accent edge while IsActive is true, and Dock.AccentInactive while it is false. An unselected tab keeps the header fill and no edge. A replaced style is left alone: the sample paints Dock.AccentInactive when IsSelected is true, and Dock.Accent when IsSelected and IsActive are both true. Switching the active pane repaints the headers. There is one bright edge, on the active pane.

Captions

<Style TargetType="dock:DockCaption">
  <Setter Property="Focusable" Value="False" />
  <Setter Property="MinHeight" Value="32" />
  <Setter Property="Background" Value="{DynamicResource Dock.Chrome}" />
  <Setter Property="Foreground" Value="{DynamicResource Dock.Text}" />
  <Setter Property="FontFamily" Value="{DynamicResource Dock.Font}" />
  <Setter Property="Template">
    <Setter.Value>
      <ControlTemplate TargetType="dock:DockCaption">
        <Border x:Name="PART_Chrome"
                Background="{TemplateBinding Background}"
                MinHeight="{TemplateBinding MinHeight}">
          <DockPanel x:Name="PART_Bar" LastChildFill="True">
            <StackPanel x:Name="PART_Buttons"
                        DockPanel.Dock="Right"
                        Orientation="Horizontal"
                        VerticalAlignment="Center" />
            <Border x:Name="PART_Grip" Background="{TemplateBinding Background}">
              <Grid>
                <ContentPresenter />
                <StackPanel x:Name="TitleRow" Orientation="Horizontal" IsHitTestVisible="False">
                  <TextBlock x:Name="PART_Title"
                             Text="{TemplateBinding Title}"
                             Margin="10,0,8,0"
                             VerticalAlignment="Center"
                             Foreground="{TemplateBinding Foreground}"
                             FontFamily="{TemplateBinding FontFamily}" />
                </StackPanel>
              </Grid>
            </Border>
          </DockPanel>
        </Border>
        <ControlTemplate.Triggers>
          <Trigger Property="Role" Value="Strip">
            <Setter TargetName="TitleRow" Property="Visibility" Value="Collapsed" />
          </Trigger>
          <Trigger Property="IsAccented" Value="True">
            <Setter Property="Background" Value="{DynamicResource Dock.Panel}" />
            <Setter TargetName="PART_Chrome" Property="BorderBrush" Value="{DynamicResource Dock.AccentInactive}" />
            <Setter TargetName="PART_Chrome" Property="BorderThickness" Value="0,2,0,0" />
          </Trigger>
          <MultiTrigger>
            <MultiTrigger.Conditions>
              <Condition Property="IsAccented" Value="True" />
              <Condition Property="IsActive" Value="True" />
            </MultiTrigger.Conditions>
            <Setter TargetName="PART_Chrome" Property="BorderBrush" Value="{DynamicResource Dock.Accent}" />
          </MultiTrigger>
          <Trigger Property="Role" Value="Flyout">
            <Setter TargetName="PART_Chrome" Property="BorderBrush" Value="{DynamicResource Dock.AccentInactive}" />
            <Setter TargetName="PART_Chrome" Property="BorderThickness" Value="0,2,0,0" />
          </Trigger>
          <MultiTrigger>
            <MultiTrigger.Conditions>
              <Condition Property="Role" Value="Flyout" />
              <Condition Property="IsActive" Value="True" />
            </MultiTrigger.Conditions>
            <Setter TargetName="PART_Chrome" Property="BorderBrush" Value="{DynamicResource Dock.Accent}" />
          </MultiTrigger>
        </ControlTemplate.Triggers>
      </ControlTemplate>
    </Setter.Value>
  </Setter>
</Style>

A custom caption style hosts the library's button cluster in PART_Buttons. If you name a Button PART_Close, PART_Pin, PART_Maximize, or PART_Menu, the caption gives it the library button's automation name, tooltip, glyph, and visibility, and takes the library button out of the cluster so it doesn't show twice. A template with neither the named button nor PART_Buttons simply has no such button. The default template, used while Style is null, puts the cluster in PART_Bar instead.

PART_Grip is the drag surface; without it, the whole caption is. A strip caption (Role is Strip) shows the tab strip as its content, so its template needs a ContentPresenter. The sample hides the title row for that role. PART_Title shows Title, and a template without it shows no title.

IsAccented is true for the one-pane top bar. That bar uses the panel fill and a 2px edge. The edge is Dock.Accent while IsActive is true and Dock.AccentInactive while it is false. IsActive is true when this caption's pane is the active pane. A split float title is active while that window is active, and it does not draw this edge. A replaced style reads IsAccented and IsActive and paints itself. The sample uses Dock.AccentInactive for the accented bar and Dock.Accent when that bar is also active.

A flyout caption stays IsAccented false and keeps the chrome fill, at 28px unless your style sets a height. Its 2px top edge still follows IsActive. The sample paints that edge from Role being Flyout. A bottom tool caption, with tabs under the content and more than one pane, keeps the chrome fill and draws no edge.

Drop preview and guides

<Style TargetType="dock:DockDropPreview">
  <Setter Property="Background" Value="{DynamicResource Dock.Guide}" />
  <Setter Property="BorderBrush" Value="{DynamicResource Dock.Accent}" />
  <Setter Property="BorderThickness" Value="1" />
  <Setter Property="CornerRadius" Value="2" />
  <Setter Property="Template">
    <Setter.Value>
      <ControlTemplate TargetType="dock:DockDropPreview">
        <Border Background="{TemplateBinding Background}"
                BorderBrush="{TemplateBinding BorderBrush}"
                BorderThickness="{TemplateBinding BorderThickness}"
                CornerRadius="{TemplateBinding CornerRadius}" />
      </ControlTemplate>
    </Setter.Value>
  </Setter>
</Style>

DockDropPreview has no named parts. SmartDock.Core decides where the rectangle goes, and the template only paints it. CornerRadius is a property on the control. The default border thickness is 0 and Dock.GuideBorder is transparent, so the stock preview is a plain fill; the sample adds a 1px accent edge. The preview never takes mouse input.

DockGuideButton names PART_Chrome, PART_Plate, and PART_Mark. Hit testing uses the guide rectangles in SmartDock.Core, so the button doesn't take mouse input either. The library moves PART_Mark only while Style is null; a replaced style draws its own icon. Side is Left, Right, Top, Bottom, or Center, where Center tabs the pane into the group. IsRootEdge is true for the buttons in the middle of a host edge, and IsHot is true while the pointer is over the guide. The default template switches to the accent fill when IsHot is true.

DockToolBarTray adds one child per band to PART_Bands, which must be a Panel. If it's a StackPanel, the tray sets it to Horizontal on the left and right edges and Vertical on the top and bottom. Without PART_Bands the tray has nowhere to put bands, so it is removed and its toolbars don't appear.

DockToolBarGrip has no named parts. Its Orientation is Horizontal in a top or bottom band and Vertical in a left or right band, where the grip sits at the top.

DockToolBarCaption is the title bar of a floating toolbar. PART_Close hides every visible toolbar in that window. On a vertical float that button is a 32/3 DIP box (about 10.7) and its glyph is two thirds of the template's font size. A close button from the host's own template gets the same size. A horizontal caption keeps the width and font size from the template. PART_Grip drags the whole window, and double-clicking PART_Grip docks them all back. PART_Title shows Title. A shared window joins the toolbar titles with a comma. The text trims when the window is narrow, and a trimmed title has a tooltip with the full text. The caption's context menu has Vertical, Dock Back, and Close. Vertical flips every toolbar in the window, and Dock Back and Close act on all of them. Pressing anywhere on the caption except a button also starts a drag, even without PART_Grip, and double-clicking the caption docks the window back too. Without PART_Close there is no close button. A grip on one toolbar still drags, reorders, or tears off that toolbar, and double-clicking it docks only that one.

DockToolBarCustomize is the chevron that opens the Add or Remove Buttons menu. It has no named parts, and Click is handled by the control, so a replaced template still opens the menu. DockToolBarDrop is the line shown while you drag a toolbar. It has no named parts, doesn't take mouse input, and is filled with Dock.Accent by default.

Leaving parts out

<ResourceDictionary xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
                    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
                    xmlns:dock="clr-namespace:SmartDock;assembly=SmartDock">
  <!-- Not merged by StylingWindow. A header template with neither PART_Close nor PART_ButtonHost has no close button. -->
  <Style TargetType="dock:DockTabHeader">
    <Setter Property="Template">
      <Setter.Value>
        <ControlTemplate TargetType="dock:DockTabHeader">
          <TextBlock Text="{TemplateBinding Title}"
                     Margin="8,4"
                     VerticalAlignment="Center"
                     Foreground="{DynamicResource Dock.Text}"
                     FontFamily="{DynamicResource Dock.Font}" />
        </ControlTemplate>
      </Setter.Value>
    </Setter>
  </Style>
</ResourceDictionary>

StylingWindow doesn't use this dictionary. It's here to show what happens when a part is missing. Used as the implicit DockTabHeader style, it gives headers with no close button and no pin, because the template names neither the buttons nor PART_ButtonHost. Dragging and selecting still work. A caption works the same way: if it names neither PART_Buttons nor PART_Close, it has no close button.
